# 科研日志 - 2026-10-07

- [ ] 完成 tractography、TDI、connectome 和节点标签 QC。

## 当前进展：从原理到文件

本项目需要比较结构连接（SC）与功能连接（FC）。SC 不是直接从 fMRIPrep BOLD 得到，而是由原始 DWI 经 micapipe 建模、tractography 和 atlas 汇总得到；FC 会在之后从既有 clean BOLD 提取。两者只有在使用同一组脑区标签、完全相同行列顺序时才能逐边比较。

这次刚完成的不是“最终 SC-FC 结果”，而是将单 session tractography 的 atlas 级 connectome 转为一张可与未来皮层 FC 对齐的 **400 节点候选 SC**。原始 450 节点矩阵含有非皮层和 medial-wall 节点，并且以只填上三角的格式保存；因此必须按 LUT 去除不纳入主分析的节点、镜像上三角、置零对角线，并保存标签表。该过程的成功证据是 400 x 400、对称矩阵和 400 行标签表，而不是已获得 coupling。

当前仍缺少两类检查：TDI/tractography 的视觉合理性，以及未来 FC 的标签顺序是否与这 400 行标签表完全相同。完整放行状态见 [[关于科研经历/01-研究项目/MyConnectome/数据与运行记录/micapipe结构处理与SC-FC实施方案#阶段验证台账|项目阶段验证台账]]；一般方法依据见 [[关于科研经历/02-方法库/神经影像/micapipe DWI 到结构连接工作流#方法原则如何落到检查|方法原则与检查]]。

## 已确认进展

- `SC-10M_acq-ses-013` 已完成 1/1 步，状态为 `COMPLETED`，总时长约 214 分钟。
- micapipe 已生成 tractography/connectome 衍生物，并将一个 2200 x 2200 的完整 connectome 表示切分为 450 x 450 atlas 级表示。
- 450 节点不应自动等同于主分析所需的 400 个皮层 `Schaefer-400` 节点；其实际标签和顺序仍待检查。
- atlas 级 `full-connectome.shape.gii` 是保留的 SIFT2 边权矩阵；micapipe 在生成 GIFTI 后会删除中间 `.txt` 矩阵。默认配置也不保留 `.tck` tractogram，因此这些文件未出现在输出列表是预期行为。
- micapipe v0.2.3 的 450 节点由 48 个皮层下/小脑节点、2 个 medial-wall 占位节点与 400 个 Schaefer 皮层 parcel 构成。根据内置 LUT 的升序 `mics` 顺序，400 个皮层节点对应 450 矩阵的 Python 索引 `49:249` 和 `250:450`。
- 修正 Docker 命令已成功生成 400 x 400 与 400 标签；其原始 `Symmetric: False` 是预期的上三角编码，而非 SC 失败。micapipe 未使用 `tck2connectome -symmetric`，因此已镜像上三角并置零对角线，生成用于无向 SC/FC coupling 的候选矩阵。

## QC、结果与待验证项

- **已通过的检查：** SC 容器流程完成；connectome slicer 成功生成 450 x 450 atlas 级输出；400 节点 SIFT2 和 edge-length 矩阵已成功派生、对称化并配套 400 行标签表。
- **待检查：** TDI 的空间合理性；派生 SC 是否与预期边权定义一致；FC 提取后是否能以标签表严格验证节点顺序。
- **运行环境问题：** Docker daemon 无法直接 bind mount 嵌套 connectomes 目录；需改为挂载已验证可访问的 derivatives 父目录。
- **不应据此作出的结论：** SC 处理完成不等于 tractography 或 connectome 可用于分析；450 节点矩阵不能直接与 400 节点 FC 相关；单 session SC 不能定义稳定 SC。
